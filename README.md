# CFT Knowledge Assistant

Информационный ИИ-ассистент исключительно по АО «Центр Финансовых Технологий» (ЦФТ).
Проект не содержит предметных сценариев других компаний или вузов.

## Возможности

- Диалоговый веб-интерфейс с созданием нового диалога и историей.
- Продолжение разговора в пределах одной сессии.
- Изоляция сессий по подписанному случайному browser token; UUID владельца нельзя подменить без серверного секрета. Это защита локального MVP от угадывания/подмены ID, но не замена корпоративному SSO.
- RAG по материалам ЦФТ: hybrid retrieval (local multilingual E5 dense embeddings + FastEmbed BM25 + RRF).
- Ответы с нумерованными ссылками [1], [2] на источники; frontend показывает соответствующие документы, разделы и страницы, если они доступны.
- Реестр документов и live-статистика базы знаний.
- Повторяемая индексация с SHA-256 версионированием и сохранением предыдущих версий.
- Инкрементальный обход сайтов с ограничением глубины и числа страниц, allowlist доменов (по умолчанию только cft.ru и поддомены), DNS-проверкой публичных адресов, проверкой redirect-целей, фильтрацией служебных URL и HTTP-проверкой изменений.
- Защита от prompt injection на уровне system prompt и границ доверия; у модели нет произвольных инструментов.
- Health endpoints, диагностические логи с session ID/источниками/временем, healthchecks, persistent volumes и скрипты резервного копирования/восстановления.

## Технологический стек

Стек: FastAPI, Python 3.11, PostgreSQL, SQLAlchemy, Qdrant, DeepSeek API через
OpenAI-compatible SDK, FastEmbed (локальные dense E5 + BM25), Scrapy,
BeautifulSoup/lxml, pypdf, python-docx, Docling + RapidOCR, Nginx, HTML, CSS и
JavaScript. Runtime-зависимости перечислены в `backend/requirements.txt`; минимальные
зависимости индексации — в `backend/requirements-ingest.txt`; тяжёлый OCR вынесен
в `backend/requirements-ingest-ocr.txt`, а crawler — в `backend/requirements-crawler.txt`.

DeepSeek API используется только для генерации ответов. Dense-поиск выполняется
локально через FastEmbed с `intfloat/multilingual-e5-large` (1024 измерения) на CPU
через ONNX Runtime; PyTorch, CUDA и NVIDIA для dense-эмбеддингов не нужны. Для
запросов и фрагментов документов используются отдельные query/passage-режимы E5.
Лексический поиск — локальный FastEmbed BM25, который дополняет семантический поиск
точным совпадением терминов, аббревиатур и названий продуктов. Обычные PDF обрабатываются pypdf, DOCX — python-docx, HTML — BeautifulSoup/lxml.
Тяжёлый Docling + RapidOCR нужен только для сканированных/смешанных PDF и вынесен
в отдельный OCR-образ; обычная индексация не устанавливает PyTorch и CUDA/NVIDIA.
Crawler также имеет отдельный лёгкий образ и не устанавливает Docling. В Docker volume `modelcache` остаются только
кэш локальной E5-модели, BM25 и Docling/OCR.

## Быстрый запуск Docker

Требуется Docker Engine/Desktop с Docker Compose v2 и доступ в интернет для
загрузки образов, Python-пакетов и локальной E5-модели (при первом запуске), а также моделей Docling (при первом OCR).

1. Создайте конфигурацию:

   ```bash
   cp .env.example .env
   ```

   В Windows PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

2. В `.env` задайте уникальные случайные значения `POSTGRES_PASSWORD` (32+ символа), `CLIENT_TOKEN_SECRET` (32+ символа) и `DEEPSEEK_API_KEY`. Ключ для эмбеддингов не нужен: E5 запускается локально. `CLIENT_TOKEN_SECRET` подписывает browser-токены; при его смене ранее созданные токены перестанут работать.
   Не используйте пароль-заглушку в рабочем окружении. Не добавляйте `.env` в Git.

3. Запустите основной стек приложения:

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

   По умолчанию запускаются только постоянно работающие сервисы: PostgreSQL,
   Qdrant, Backend и Frontend. Контейнер индексации в обычный запуск не входит,
   поэтому приложение не ждёт завершения обработки документов. На первом запуске
   база знаний будет пустой до выполнения следующего шага.

4. Соберите открытые материалы с официального сайта ЦФТ (рекомендуется для первичного наполнения; повторяйте после обновления сайта):

   ```bash
   docker compose --profile crawl run --build --rm crawler
   ```

   Затем выполните первичную индексацию (и повторяйте после добавления/изменения материалов в `data/raw/`):

   ```bash
   docker compose --profile ingest run --build --rm ingestion
   ```

   Это лёгкий режим для текстовых PDF, DOCX, HTML, TXT и MD. Если среди PDF есть
   сканы или страницы без извлекаемого текста, используйте OCR-образ:

   ```bash
   docker compose --profile ingest-ocr run --build --rm ingestion-ocr
   ```

   OCR-образ тяжелее, поскольку Docling использует PyTorch для layout/table-моделей.
   На Linux без GPU сборка принудительно использует CPU wheels PyTorch, а не CUDA/NVIDIA.

   Команда автоматически дождётся готовности PostgreSQL и Qdrant, обработает
   документы и завершится. Backend и Frontend при этом продолжают работать.
   Повторный запуск безопасен: неизменившиеся документы пропускаются по SHA-256.

5. Откройте:

   - Frontend: http://localhost:8080
   - Health: http://localhost:8080/health/ready
   - Backend Swagger: http://localhost:8080/docs (если в `.env` установлено `APP_ENV=development`).

   PostgreSQL и Qdrant не опубликованы на хостовые порты. Backend доступен
   только внутри Docker-сети через Nginx. Frontend привязан к `127.0.0.1`.

Если порт занят, измените `FRONTEND_PORT` в `.env`.

## Работа с базой знаний

Поддерживаемые входные форматы: PDF, DOCX, HTML/HTM, TXT, MD. Текстовые PDF обрабатываются pypdf. Сканированные/смешанные PDF требуют отдельного OCR-образа Docling + RapidOCR (профиль `ingest-ocr`).

Положите вручную проверенные материалы ЦФТ в `data/raw/approved/` (такие файлы разрешены к индексации даже без ключевых слов ЦФТ в тексте). Сборщик по умолчанию стартует с `https://www.cft.ru/` и обходит только разрешённые домены. Параметры обхода задаются в `.env`:

```env
CRAWL_START_URLS=https://www.cft.ru/
CRAWL_MAX_PAGES=300
CRAWL_MAX_DEPTH=2
CRAWL_ALLOWED_DOMAINS=cft.ru
CRAWL_APPROVED_EXTERNAL_DOMAINS=
```

Глубина `0` означает только стартовую страницу, `1` — ссылки с неё, `2` — ещё один уровень ссылок. По умолчанию разрешены только `cft.ru` и его поддомены. Чтобы разрешить дополнительный официальный домен, добавьте его одновременно в `CRAWL_ALLOWED_DOMAINS` и `CRAWL_APPROVED_EXTERNAL_DOMAINS`; не добавляйте пользовательские или неизвестные домены. Каждый запрос, включая redirect, повторно проверяется на allowlist и публичный DNS/IP. Соблюдается `robots.txt`. Исключаются служебные пути (поиск, авторизация, личный кабинет и т. п.), параметры поиска/фильтрации/сортировки, трекинговые параметры и медиа/архивы. Загружаются PDF, DOCX, HTML, TXT и MD; сканированные PDF требуют OCR-профиля.

Для первичного сбора и последующих обновлений:

```bash
docker compose --profile crawl run --build --rm crawler
docker compose --profile ingest run --build --rm ingestion
```

Состояние обхода хранится в `data/raw/crawled/.crawl_state.json`. Для неизменённых страниц используются `ETag`/`Last-Modified`, если сервер их поддерживает; иначе содержимое сравнивается по SHA-256. Повторная индексация неизменённых документов пропускается по контрольной сумме текста. Отчёт обхода — `data/processed/crawl_report.json`, отчёт индексации — `data/processed/ingestion_report.json`. URL, которые не встретились в полном завершённом обходе, отмечаются как возможно исчезнувшие; они не удаляются автоматически из Qdrant.
Для сканированных PDF вместо этого используйте `docker compose --profile ingest-ocr run --build --rm ingestion-ocr`.

`ingestion` — одноразовый сервис с профилем `ingest`: он запускается только
по запросу, не блокирует старт Backend и завершает работу после обновления
индекса. Для обычной работы ассистента этот контейнер не нужен.

В `data/processed/ingestion_report.json` сохраняется отчёт: число найденных,
обработанных документов, число фрагментов, объём текста и ошибки.

В исходном репозитории присутствует приложенная справка DOCX и manifest ранее запланированных URL, но не полный snapshot собранных веб-страниц. Поэтому для наполнения с нуля сначала запустите профиль `crawl`, затем `ingest`. `data/raw/ЦФТ (1).docx` — приложенная справка ЦФТ. DOCX обрабатывается python-docx: извлекаются абзацы, заголовки и таблицы. Docling применяется для OCR сканированных/смешанных PDF в отдельном OCR-образе. Для веб-страниц сохраняются исходный URL и заголовок.
Дата получения записывается в payload индекса. Если дата публикации/версия
не присутствует в исходном материале, она не придумывается.

## Масштабирование и отказоустойчивость

- PostgreSQL и Qdrant используют именованные persistent volumes.
- История и владельцы сессий находятся в PostgreSQL; векторный индекс — в Qdrant.
- Backend хранит диалоговое состояние в PostgreSQL. Внутри одного процесса запросы одной сессии сериализуются, а повтор запроса с тем же `request_id` возвращает сохранённый ответ вместо повторной генерации. Текущий Compose-профиль рассчитан на одну Backend-реплику: перед масштабированием на несколько реплик требуется общий PostgreSQL advisory lock и проверенная динамическая балансировка Nginx. Не запускайте `--scale backend=2` в этой редакции.
- SQLAlchemy использует пул соединений, `pool_pre_ping`, таймаут подключения
  и recycle соединений.
- Контейнеры перезапускаются при сбое; readiness проверяет PostgreSQL и Qdrant.
- При недоступности модели/поиска API возвращает контролируемую ошибку 503; для LLM заданы timeout/retries, ограничение параллельности и простой circuit breaker с cooldown. Резервного LLM-провайдера нет.
- Индексация сначала загружает новую версию неактивной, затем переключает
  активную версию. Предыдущие версии сохраняются для аудита и возможного отката.
  Не меняйте модель эмбеддингов или размерность в существующей коллекции без
  создания новой коллекции и полной переиндексации. В этой редакции используется отдельная коллекция `knowledge_chunks_e5_large_v2` (1024 измерения).
- Резервные копии PostgreSQL и Qdrant создаются `scripts/backup.sh`; восстановление — `scripts/restore-backup.sh`. Qdrant кратковременно останавливается для консистентного архива storage volume. Храните backups вне этого хоста и периодически проверяйте восстановление.

Масштабирование backend требует CPU и памяти под локальную E5-модель в каждой реплике; скачанные файлы модели разделяются через Docker volume. Для высокой доступности самой БД и Qdrant нужны их кластерные
конфигурации; одиночные контейнеры Compose обеспечивают перезапуск и сохранность
данных, но не являются HA-кластером. Размер пула PostgreSQL ограничивает
число соединений каждой реплики; при дальнейшем росте потребуется пулер
соединений и отдельное масштабирование PostgreSQL/Qdrant.

## API

- `POST /api/sessions` — создать диалог.
- `GET /api/sessions` — список диалогов текущего browser client.
- `GET /api/sessions/{session_id}/history` — история.
- `POST /api/chat` — получить ответ и источники.
- `GET /api/knowledge/stats` — статистика базы.
- `GET /api/knowledge/sources` — реестр источников.
- `GET /api/knowledge/files/{source_id}` — открыть/скачать исходный файл ЦФТ.
- `GET /health/live` — liveness.
- `GET /health/ready` — readiness PostgreSQL + Qdrant.

Frontend получает подписанный токен через `POST /api/client/bootstrap` и хранит его в localStorage; для `/api/sessions` и `/api/chat` передаётся `X-Client-Token`. Подписанный токен предотвращает подделку owner UUID и случайный перебор, но остаётся bearer credential: при краже токена возможна impersonation. Это не полноценная корпоративная аутентификация. Перед публикацией в корпоративной сети ЦФТ подключите OIDC/SSO и проверку ролей на backend. Не публикуйте приложение в Интернет без корпоративной аутентификации и HTTPS.

Пример:

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/client/bootstrap | python -c "import sys,json; print(json.load(sys.stdin)['client_token'])")
curl -X POST http://localhost:8080/api/chat \
  -H "Content-Type: application/json" \
  -H "X-Client-Token: $TOKEN" \
  -d '{"message":"Какие продукты ЦФТ описаны в базе знаний?"}'
```

Для ручного API-тестирования сначала вызовите `POST /api/client/bootstrap`, затем передайте возвращённый `client_token` в заголовке `X-Client-Token`.

## Проверки

Из `backend/`:

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m compileall app ingest
```

Тесты покрывают chunking/сохранение структуры, поиск, сохранение/изоляцию сессий, подписанные browser-токены, контекстный поисковый запрос и защитные tripwire. Регрессионные проверки prompt injection находятся в `backend/tests/test_prompt_injection.py`; описание сценариев — `docs/security_test_cases.md`. Для запуска: `cd backend && python -m pytest -q tests/test_prompt_injection.py tests/test_agent.py tests/test_security.py`. Для adversarial smoke-test реального провайдера выполните `cd backend && python scripts/security_smoke.py`; результат требует человеческой оценки и не является сертификатом безопасности.

## Безопасность и ограничения

- В репозитории нет API-ключей; используйте `.env` локально и секрет-хранилище
  в deployment.
- Если прежний `.env` с реальными секретами уже передавался или попадал в Git,
  смените пароль БД и отзовите/перевыпустите API-ключ.
- Содержимое документов и история — недоверенные данные, а не инструкции.
- Модель не имеет shell, SQL или произвольных HTTP-инструментов.
- Crawler соблюдает robots.txt, ограничивает скорость/параллельность, работает по allowlist, проверяет публичность DNS-адресов и redirect-целей, не обходит авторизацию, CAPTCHA, paywall или запреты владельца сайта.
- Без корпоративной аутентификации нельзя открывать приложение в публичную сеть.
- Схема создаётся через SQLAlchemy `create_all` и идемпотентные добавочные PostgreSQL-изменения для новых полей. Для длительного промышленного сопровождения следует перейти на версионируемые миграции; текущий небольшой проект не добавляет отдельную миграционную платформу.
- RRF-порог `RETRIEVAL_MIN_SCORE` является стартовой настройкой, а не универсальным порогом качества: его следует калибровать на размеченном наборе вопросов ЦФТ.
- Сериализация запросов по одной сессии и idempotency key работают в одной Backend-реплике. Многорепличный запуск пока намеренно не включён.
- LLM circuit breaker снижает лавинообразные повторные вызовы при сбоях, но не заменяет резервного провайдера: во время недоступности DeepSeek генерация недоступна.
- Точность RAG зависит от полноты базы и должна оцениваться на актуальном наборе
  вопросов экспертов ЦФТ. Если факта нет в источниках, агент должен сообщить
  об отсутствии подтверждения.


## DeepSeek, локальные эмбеддинги, Docling и OpenCode

Для генерации ответов используется DeepSeek API через OpenAI-совместимый SDK:
`LLM_BASE_URL=https://api.deepseek.com`, `LLM_MODEL=deepseek-flash`. Используйте
актуальное имя модели из официального списка DeepSeek. Ключ хранится только в
`DEEPSEEK_API_KEY` в `.env` и не попадает во frontend или репозиторий.

Dense encoder работает локально через FastEmbed: `intfloat/multilingual-e5-large`
(1024 измерения, мультиязычный поиск). Для запросов и индексируемых фрагментов
используются отдельные адаптеры `query_embed` и `passage_embed`. Модель работает на CPU
через ONNX Runtime; PyTorch, CUDA, NVIDIA и API-ключ для эмбеддингов не нужны.
FastEmbed BM25 также работает локально и дополняет семантический поиск. Кэш модели
сохраняется в Docker volume `modelcache`. При генерации ответа найденные фрагменты
и вопрос передаются DeepSeek API, поэтому для закрытых/персональных данных требуется
проверить разрешение на использование внешнего LLM. Обычный ingestion-образ не содержит
Docling/PyTorch и обрабатывает текстовые PDF через pypdf, DOCX через python-docx.
Для сканированных/смешанных PDF предусмотрен отдельный `ingestion-ocr` образ с
Docling (с включённым стандартным RapidOCR) и CPU-only PyTorch. Crawler собирается отдельно и не тащит
ни runtime API-зависимости, ни OCR-стек.

Ollama не используется и не нужна: языковая модель вызывается по DeepSeek API.
OpenCode — отдельный инструмент разработчика для работы с кодом; его не нужно
добавлять в Docker Compose или запускать в runtime приложения.

**Важно при переходе на локальный E5:** используется новая коллекция Qdrant
`knowledge_chunks_e5_large_v2` размерностью 1024. Все материалы индексируются заново:
векторы Jina и E5 нельзя смешивать, даже если размерность совпадает. Не смешивайте векторы разных моделей.


## Резервное копирование

После запуска основного Compose-стека выполните из корня проекта:

```bash
./scripts/backup.sh
# Windows: запускать через Git Bash/WSL
./scripts/restore-backup.sh ./backups/ИМЯ_КАТАЛОГА
```

Backup содержит логический дамп PostgreSQL и архив Qdrant storage volume. Скрипт backup кратковременно останавливает Qdrant для консистентного копирования; выполняйте его в согласованное окно. Восстановление разрушительно для текущих данных и требует явного подтверждения. Проверяйте восстановление на отдельном стенде.

## Изменения редакции 1.6

- Структурный chunking сохраняет заголовки, абзацы и маркеры страниц; версии контента учитывают сохранённую структуру.
- Поисковый запрос учитывает недавний контекст коротких follow-up вопросов; добавлен порог отсечения слабых RRF-результатов.
- Источники нумеруются в контексте, модель запрашивается указывать ссылки `[n]`, backend удаляет ссылки на несуществующие номера.
- Повторные отправки поддерживают `request_id`; в одной реплике запросы одной сессии сериализуются.
- Browser owner ID теперь передаётся в подписанном токене; это защита от подделки ID, не SSO.
- Crawler по умолчанию ограничен доменами ЦФТ, блокирует непубличные DNS/IP и проверяет redirect-цели.
- Добавлены TTL-очистка сессий, ограниченная выдача истории, ограничение параллельных LLM-запросов, CSP, резервное копирование и smoke-test prompt injection.


## Обновление до 1.6.1 после OCR/BM25 hotfix

В `.env` обязательно укажите:

```env
QDRANT_COLLECTION=knowledge_chunks_e5_large_v2
APP_VERSION=1.6.1-cft-rag-hardening
```

Для сканированных PDF сначала соберите OCR-образ (при сборке Docling скачивает
модели в образ, включая набор для кириллицы), затем выполните:

```bash
docker compose --profile ingest-ocr run --build --rm ingestion-ocr
```

Для обычной индексации без OCR:

```bash
docker compose --profile ingest run --build --rm ingestion
```

В 1.6.1 используется новая Qdrant-коллекция v2, потому что исправлено построение
BM25-векторов документов. Это намеренно заставляет переиндексировать все документы.
Не удаляйте старую коллекцию v1, пока не проверите статистику, качество поиска и
ответы на контрольных вопросах. После успешной проверки старую коллекцию можно
удалить вручную из Qdrant Dashboard/API, если резервная копия сохранена.
